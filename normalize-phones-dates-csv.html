How to Normalize US Phone Numbers & Dates in a CSV

Five phone formats and six date formats in one column is the #1 reason CRM imports blow up. Here's the exact normalization I run on every file: one target format per column, and anything unfixable gets blanked — never faked.

Phones: everything → E.164 (+1XXXXXXXXXX)

The trick is to throw away all formatting first, then look at what digits are left:

import re

def norm_phone(raw):
    digits = re.sub(r"\D", "", raw or "")
    if len(digits) == 10:
        return "+1" + digits, False       # 2125550142 -> +12125550142
    if len(digits) == 11 and digits.startswith("1"):
        return "+" + digits, False        # 1-212-555-0142 -> +12125550142
    return "", True                        # unfixable -> blank, flagged

Scope note: this handles US numbers only (10 digits, optional leading 1). International numbers need a library like phonenumbers — or just send me the file.

Dates: everything → ISO-8601 (YYYY-MM-DD)

Try the common formats in order, fall back to fromisoformat, blank the rest:

from datetime import datetime

DATE_FORMATS = (
    "%Y-%m-%d", "%m/%d/%Y", "%d/%m/%Y", "%m-%d-%Y", "%d-%m-%Y",
    "%Y/%m/%d", "%b %d, %Y", "%B %d, %Y", "%m/%d/%y", "%d.%m.%Y",
    "%m-%d-%y", "%d-%m-%y", "%d-%b-%Y", "%d-%B-%Y",
)

def norm_date(raw):
    s = (raw or "").strip()
    if not s:
        return "", True
    for fmt in DATE_FORMATS:
        try:
            return datetime.strptime(s, fmt).date().isoformat(), False
        except ValueError:
            pass
    try:
        return datetime.fromisoformat(s).date().isoformat(), False
    except ValueError:
        return "", True

Ambiguity warning: 01/02/2023 parses as January 2 (US order wins, since %m/%d/%Y comes before %d/%m/%Y in the list). If your data is European day-first, swap those two entries. Dates the parser can't read are blanked and counted in dates_blanked — the row stays.
